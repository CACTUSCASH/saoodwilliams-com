    MERGE RULES

    Same operations. Same document.

    Every change has a client ID and a Lamport counter. A field accepts the larger counter. Equal counters are ordered by client ID, so every tab reaches the same answer even when messages arrive in a different order.

    Editing text in one tab and color in another preserves both changes. If both tabs edit the same field, one value wins by that ordering. This is field-level merging, not character-by-character shared text editing.

    Deletion tombstones are permanent. Undo creates fresh operations; restoring a deleted shape gives it a new ID. A late update cannot revive the old one.

    Browser mode connects tabs with BroadcastChannel. The optional local server stores operations in SQLite and streams new ones over SSE. Presence here counts only the browser tabs that actually announce themselves.
