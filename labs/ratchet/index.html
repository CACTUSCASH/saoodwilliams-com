          HOW IT WORKS

          Two ratchets,
          one conversation.

          01

          X3DH

          Bob publishes a signed prekey and one-time prekeys. Alice verifies the signature, mixes three or four X25519 outputs through HKDF and starts the ratchet. A one-time prekey is deleted only after the first message authenticates.

          02

          Double Ratchet

          A symmetric chain gives every message its own key, and a new DH key on every reply turns the root chain. Late messages open with stored skipped keys, capped by MAX_SKIP (50) and a 100-key store.

          03

          Limits

          X25519 and Ed25519 are plain BigInt JavaScript, readable but not constant time; use a vetted library for real traffic. Identity keys pair X25519 with a separate Ed25519 key instead of XEdDSA. Headers are not encrypted, and the server and network are simulated here.
